The generic runtime-backed selector distinguishes PRE_EXECUTOR, POST_EXECUTOR and POST_ACCEPTANCE. Before dispatch it rejects unrecorded invocation/completion/candidate artifacts, new gate-owned helpers, unauthorized imports and any wrapper difference from the immutable baseline. It selects the latest accepted certified extension and reuses the existing strict provenance validator, including reviewed artifact hashes, commit ancestry, module-change history and freshly compiled declaration fingerprints. After successful executor completion, the controller records the actual invocation identity, immutable baseline hash, materialized wrapper/helper hashes and executor-final hash. The candidate path requires these matching records and the current-gate preservation certificate. Accepted extensions continue through the existing immutable accepted-chain validator. Neither status text nor an empty/reserved directory constitutes execution or a candidate.
